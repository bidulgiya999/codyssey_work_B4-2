# 한 단계씩 함께 진행하는 학습 방법

이 문서는 [통합 교안](complete-course.md)을 실제로 공부하는 방법을 설명합니다. 목표는 명령을 복사해 실행하는 것을 넘어, 선택 이유와 결과를 본인의 말로 설명하는 것입니다.

## 1. 한 단계의 목적과 명령을 먼저 읽습니다

안내자는 지금 확인하려는 내용, 명령과 옵션의 의미, 입력할 터미널을 설명합니다. 학습자는 실행 전에 예상 결과를 말합니다. PowerShell과 Ubuntu를 구분하며 프롬프트나 출력 예시는 입력하지 않습니다.

**용어 설명:** 명령은 컴퓨터에 요청하는 작업, 옵션은 작업 방식을 지정하는 값, 프롬프트는 입력을 기다리는 셸의 표시입니다.

## 2. 학습자가 직접 입력하고 실제 출력을 공유합니다

한 번에 한 단계만 입력합니다. 실제 결과를 그대로 보내며 오류도 생략하지 않습니다. 출력이 없으면 “출력 없이 프롬프트로 돌아왔다”고 기록합니다. 이전 실험의 결과를 자신의 새 실행 결과로 사용하지 않습니다.

**용어 설명:** 출력은 명령이 표시한 결과입니다. 표준 출력은 일반 결과이고 표준 오류는 진단 메시지 등을 보내는 별도 경로입니다. 오류가 이 구분을 항상 엄격히 따르는 것은 아닙니다.

## 3. 왜 그런 결과가 나왔는지 함께 해석합니다

안내자는 각 열·숫자·단위·상태와 출력 형식의 이유를 설명합니다. 정상·이상·판단 보류를 구분하고, 판단 근거와 추가 확인 항목을 제시합니다. 증거 링크는 [파일별 해설](evidence-reading-guide.md)과 함께 읽습니다.

예를 들어 `whoami`가 `jae0608`을 출력하면 현재 명령을 실행하는 계정 이름을 뜻합니다. `id -u`의 `1000`은 사용자의 숫자 식별자이며 CPU나 메모리 사용률이 아닙니다. UID가 0이 아니므로 root가 아닌 계정임을 확인합니다.

**용어 설명:** 관측 사실은 실제 출력에서 읽은 내용이고, 추론은 여러 사실을 연결한 판단입니다. 출력 하나가 모든 실행 조건을 보장하지는 않습니다.

## 4. 짧은 질문으로 이해를 확인합니다

안내자는 “왜 이 명령을 썼나요?”, “이 숫자는 무엇의 단위인가요?”, “이 결과만으로 무엇까지 알 수 있나요?”처럼 질문합니다. 학습자는 자신의 말로 답합니다.

예: “`id -u`가 1000이면 무엇을 확인한 걸까요?”  
답변의 핵심: “현재 계정 UID가 1000이고 root의 UID 0이 아니므로 일반 계정 조건을 확인했습니다.”

모르겠으면 모른다고 말합니다. 안내자는 다른 예시와 쉬운 표현으로 다시 설명합니다. 이해 확인은 학습을 돕는 과정이며 평가 합격이나 점수를 보장하는 절차가 아닙니다.

**용어 설명:** 이해 확인은 결과를 암기했는지보다 목적·의미·한계를 설명할 수 있는지 살피는 과정입니다.

## 5. 이해한 뒤 다음 단계로 넘어갑니다

학습자가 목적과 결과를 설명할 수 있고 다음 단계에 필요한 조건이 확인되면 진행합니다. 오류나 불명확한 결과가 있으면 원인 확인을 먼저 합니다. 처음부터 모든 명령을 한 번에 실행하지 않습니다.

순서는 환경 확인 → 파일·권한 → 환경변수·필수 파일 → 관제 준비 → OOM 비교 → CPU 비교 → Deadlock 비교 → 증거·보고서 작성입니다. 각 실험에서는 설정값을 고른 이유와 비교에서 고정한 조건도 설명합니다.

**용어 설명:** 선행 조건은 다음 작업 전에 충족해야 하는 조건입니다. 비교 실험은 조건을 통제하며 변경 전후 결과를 확인하는 절차입니다.

## 6. 학습 기록을 남깁니다

[학습 기록 양식](../templates/learning-record-template.md)에 실행 목적, 입력 명령, 실제 출력, 해석, 질문과 답변을 적습니다. 새 실행 시각·PID·증거 경로를 사용합니다. 현재 대화에서 안내를 요청하는 것만으로 프로그램이 실행되거나 설정이 변경되는 것은 아닙니다.

학습 시작 요청 예: “교안 1번부터 시작하겠습니다. 한 단계의 명령과 이유를 먼저 설명해 주세요. 제가 결과를 보내면 해석과 이해 확인 후 다음으로 진행해 주세요.”
