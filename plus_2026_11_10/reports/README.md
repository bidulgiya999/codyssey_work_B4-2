## 한 보고서를 읽는 방법

1. **Description:** 어떤 조건에서 어떤 현상을 관측했는지 봅니다.
2. **Evidence & Logs:** 실행 코드 아래 “코드 해석”으로 입력한 이유를, 출력 아래 “출력 해석”으로 값의 뜻을 봅니다. 추가 확인용 예시는 당시 실행 요약과 구분했습니다.
3. **Root Cause Analysis:** 여러 증거를 연결해 어디까지 판단했는지 봅니다.
4. **Workaround & Verification:** 한 변수의 변경 효과, 임시 조치의 한계, 수동 정리를 확인합니다.

파란 용어를 누르면 뜻과 실제 출력의 관계를 읽을 수 있습니다. 원본 링크를 누르기 전에는 각 보고서의 **“증거 링크를 누르면 무엇을 보나요?”** 표를 보세요. 파일 역할, 읽을 열·문구와 판단 범위를 안내합니다.

> 평가에서는 코드를 모두 낭독하기보다 “왜 이 명령을 썼는지 → 출력의 어느 부분을 봤는지 → 그래서 무엇을 판단했는지”를 말합니다. 모르는 구현은 확인하지 못했다고 답하고 직접 관측한 근거까지 설명합니다.
