1. monitor.sh의 역할부터 이해하기

monitor.sh
https://github.com/bidulgiya999/codyssey_work_B4-2/blob/main/plus_2026_11_10/glossary.md#monitor-sh는 앱의 메모리 증가를 만드는 프로그램이 아닙니다. 별도로 실행되는 관제 스크립트이며, 지정한 PID
https://github.com/bidulgiya999/codyssey_work_B4-2/blob/main/plus_2026_11_10/glossary.md#pid의 상태를 반복해서 읽습니다. monitor는 관찰·감시, .sh는 셸 스크립트에 흔히 사용하는 확장자입니다.

역할을 구분하면 다음과 같습니다.

agent-leak-app: 실제 작업을 수행하는 대상 앱
monitor.sh: 대상 PID의 상태를 ps로 반복 조회
CSV 파일: 조회한 시간과 수치를 저장한 결과
monitor-번호.log: 관제가 끝났다는 안내 등 별도 메시지
app.log: 대상 앱이 직접 남긴 작업·보호 종료 로그

관제 파일과 앱 로그는 서로 다른 증거입니다. RSS가 증가했다는 관제만으로 “MemoryGuard가 종료했다”고 확정하지 않고, 앱의 종료 로그를 대조했습니다.

2. 보존된 원본 코드

다음은 scripts/monitor.sh
https://github.com/bidulgiya999/codyssey_work_B4-2/blob/main/plus_2026_11_10/scripts/monitor.sh의 전체 내용입니다. 아래 번호별 해설과 함께 읽으세요.

!/usr/bin/env bash
export LC_ALL=C

if [[ $# -ne 1 || ! $1 =~ ^[1-9][0-9]*$ ]]; then
    echo "Usage: $0 PID" >&2
    exit 1
fi

pid="$1"
echo "timestamp,pid,ppid,elapsed_s,cpu_avg_pct,mem_pct,rss_kib,threads,state"

while true; do
    row=$(ps -p "$pid" \
        -o pid=,ppid=,etimes=,pcpu=,pmem=,rss=,nlwp=,stat= \
        2>/dev/null |
        awk '$8 !~ /^Z/ {
            printf "%s,%s,%s,%s,%s,%s,%s,%s", \
                $1,$2,$3,$4,$5,$6,$7,$8
        }')

    [[ -n "$row" ]] || break
    printf '%s,%s\n' "$(date -Iseconds)" "$row"
    sleep 1
done

echo "Monitoring ended: PID $pid is no longer running." >&2

3. 첫 두 줄: Bash를 선택하고 출력 형식을 일정하게 하기

!/usr/bin/env bash
export LC_ALL=C

- #!로 시작하는 첫 줄은 이 파일을 직접 실행할 때 사용할 해석기를 지정합니다. /usr/bin/env bash는 실행 환경의 PATH에서 Bash를 찾습니다.
- Bash는 명령어와 조건문·반복문을 해석하는 셸입니다. 이 파일은 Bash 문법인 [[ ... ]] 등을 사용합니다.
- LC_ALL은 언어·지역 관련 출력 규칙에 영향을 주는 환경변수
https://github.com/bidulgiya999/codyssey_work_B4-2/blob/main/plus_2026_11_10/glossary.md#environment-variable입니다. C로 두어 숫자 등의 출력 형식을 일정하게 하려는 목적입니다.
- export는 이 설정을 이후 실행되는 ps, awk 등의 자식 명령에도 전달합니다.

왜 필요한가요? 숫자와 열을 프로그램으로 읽으므로 실행할 때마다 출력 형식이 달라지지 않도록 준비한 것입니다. 앱의 메모리 한도나 CPU 설정을 바꾸는 줄은 아닙니다.

4. 입력 검사: PID 하나를 제대로 받았는지 확인하기

if [[ $# -ne 1 || ! $1 =~ ^[1-9][0-9]*$ ]]; then
    echo "Usage: $0 PID" >&2
    exit 1
fi

./monitor.sh 11373처럼 명령 뒤에 PID 하나를 전달하는 사용 방법을 검사합니다.

| 문법 | 의미 | 이 코드에서 사용하는 이유 |
|---|---|---|
| if ...; then ... fi | 조건이 참일 때 내부 명령 실행 | 잘못된 입력이면 조회를 시작하지 않음 |
| $# | 전달한 인수 개수 | 정확히 하나인지 확인 |
| -ne 1 | 숫자로 1과 같지 않음 | 인수가 없거나 여러 개면 실패 |
| || | 앞 조건 또는 뒤 조건 | 개수 오류와 형식 오류 중 하나면 실패 |
| $1 | 첫 번째 인수 | 전달받은 PID 값 |
| =~ | 정규식과 일치하는지 검사 | 숫자 형태 검사 |
| ! | 조건을 반대로 바꿈 | 숫자 형태가 아닌 경우를 실패 처리 |
| ^[1-9][0-9]*$ | 처음부터 끝까지 0보다 큰 정수 형태 | 0·음수·문자 등 제외 |
| $0 | 실행한 스크립트의 이름 또는 경로 | 사용 안내에 실행 이름 표시 |
| >&2 | 출력 위치를 표준 오류로 지정 | CSV 데이터와 안내 메시지 분리 |
| exit 1 | 상태 1로 즉시 종료 | 입력 오류를 호출한 셸에 알림 |

정규식도 나누어 보면 ^는 시작, [1-9]는 첫 숫자, [0-9]*는 뒤에 숫자 0개 이상, $는 끝입니다. 여기의 $는 정규식 끝 표시이며 $1의 변수 기호와 용도가 다릅니다.

예를 들어 PID를 빼먹으면 Usage: ./monitor.sh PID라는 사용 안내가 나옵니다. 숫자라고 해서 실제 살아 있는 PID라는 보장은 없으며, 여기서는 입력 형식만 검사합니다.

5. PID를 기억하고 CSV 제목 출력하기

pid="$1"
echo "timestamp,pid,ppid,elapsed_s,cpu_avg_pct,mem_pct,rss_kib,threads,state"

- pid="$1"은 첫 번째 인수를 pid라는 셸 변수에 저장합니다. pid는 이 스크립트 안에서 관측 대상을 기억하는 이름입니다.
- 큰따옴표는 변수를 하나의 인수로 유지하는 데 사용합니다. 이후에도 "$pid"처럼 감싸는 습관이 좋습니다.
- echo는 글자를 출력합니다. 첫 줄을 항목 이름으로 만들어 나중에 각 숫자의 뜻을 알 수 있게 했습니다.
- CSV는 쉼표로 열을 나누는 텍스트 형식입니다. 이 출력은 아직 화면이나 파일 자체를 의미하지 않습니다. 실행할 때 >를 붙이면 파일에 저장됩니다.

6. 반복문: 한 번 조회하고 끝내지 않기

while true; do
    ...
done

while은 조건이 참인 동안 내부 명령을 반복합니다. true는 성공하는 명령이므로 반복을 계속합니다. 내부의 break가 실행되면 반복문을 빠져나옵니다.

한 번의 ps
https://github.com/bidulgiya999/codyssey_work_B4-2/blob/main/plus_2026_11_10/glossary.md#ps는 그 시점의 상태입니다. 메모리가 증가하는지 알기 위해서는 여러 시점의 값을 모아야 하므로 반복문이 필요합니다.

7. ps: 대상 프로세스에서 필요한 열만 읽기

row=$(ps -p "$pid" \
    -o pid=,ppid=,etimes=,pcpu=,pmem=,rss=,nlwp=,stat= \
    2>/dev/null |
    ...)

- row=$(...)는 괄호 안 명령의 표준 출력을 받아 변수 row에 저장하는 명령 치환입니다. 앱을 실행하는 문법이 아니라 조회 결과를 담는 문법입니다.
- 줄 끝의 \는 긴 명령을 다음 줄에 이어 적기 위한 표시입니다.
- ps -p "$pid"는 특정 PID를 선택합니다. 모든 프로세스 수치를 섞지 않도록 대상을 좁힙니다.
- -o는 출력할 필드를 직접 지정합니다. 각 필드의 =는 기본 제목을 생략합니다. 제목은 앞에서 CSV 형식으로 한 번 출력했으므로 매번 필요하지 않습니다.
- 2>/dev/null은 ps의 표준 오류를 버립니다. 종료 경계의 오류가 CSV에 섞이지 않게 했지만, 실제 수집 오류도 보이지 않을 수 있다는 한계가 있습니다.
- |는 왼쪽 명령의 표준 출력을 오른쪽 명령의 입력으로 전달하는 파이프입니다. ps 결과를 awk가 받습니다.

필드의 순서가 중요합니다. 다음 awk는 이 순서대로 첫 번째부터 여덟 번째 열을 읽습니다.

| ps 필드 | CSV 열 | 단위·의미 | 이번 과제에서 보는 이유 |
|---|---|---|---|
| pid | pid | 프로세스 번호 | 같은 관측 대상인지 확인 |
| ppid | ppid | 부모 프로세스 번호 | 실행기와 작업 자식 관계 확인 |
| etimes | elapsed_s | 실행 경과 초 | 관측 시점의 경과 시간 확인 |
| pcpu | cpu_avg_pct | 실행 시간에 걸친 평균 CPU 비율 | 장기 평균 관찰; 순간 부하와 구분 |
| pmem | mem_pct | 시스템 물리 메모리에 대한 RSS 비율 | 상대적인 점유 비율 관찰 |
| rss | rss_kib | 상주 메모리, KiB | 절대 메모리 증가 추세 비교 |
| nlwp | threads | 스레드 수 | 실행 흐름 개수 확인 |
| stat | state | 프로세스 상태와 보조 표시 | 실행·대기·좀비 등 구분 |

RSS
https://github.com/bidulgiya999/codyssey_work_B4-2/blob/main/plus_2026_11_10/glossary.md#rss는 프로그램 파일 크기나 앱의 Current Heap
https://github.com/bidulgiya999/codyssey_work_B4-2/blob/main/plus_2026_11_10/glossary.md#current-heap과 같지 않습니다. 표시 단위도 KiB·MiB·MB 해설
https://github.com/bidulgiya999/codyssey_work_B4-2/blob/main/plus_2026_11_10/glossary.md#units과 함께 구분해서 읽습니다. 필드 정의는 ps 매뉴얼
https://man7.org/linux/man-pages/man1/ps.1.html에서 확인할 수 있습니다.

8. awk: 공백 구분 출력을 쉼표 구분 데이터로 바꾸기

awk '$8 !~ /^Z/ {
    printf "%s,%s,%s,%s,%s,%s,%s,%s", \
        $1,$2,$3,$4,$5,$6,$7,$8
}'

awk는 입력을 행과 열로 나누어 처리하는 도구입니다. 이 코드에서는 ps의 공백 구분 열을 읽습니다.

- awk의 $1은 입력 행의 첫 번째 열이며 $8은 여덟 번째 열입니다. 앞에서 Bash의 $1은 스크립트 첫 인수였습니다. 서로 실행되는 언어와 문맥이 다릅니다.
- 작은따옴표 '...'로 감싸 Bash가 awk 안의 $1 등을 먼저 바꾸지 않게 합니다.
- $8 !~ /^Z/는 “여덟 번째 열인 상태가 Z로 시작하지 않는 행”을 고릅니다. !~는 정규식과 일치하지 않음을 뜻합니다.
- Z는 이미 실행이 끝난 좀비 상태입니다. PID가 목록에 있더라도 살아서 작업하는 상태로 관제하지 않도록 제외했습니다.
- printf의 %s는 값을 글자로 출력할 자리입니다. 쉼표는 CSV 열 구분자입니다.
- 여기에서는 줄바꿈을 넣지 않습니다. 이후 Bash의 printf가 시간과 합쳐 한 행을 만듭니다.

9. 빈 결과면 멈추고, 있으면 시간과 함께 저장하기

[[ -n "$row" ]] || break
printf '%s,%s\n' "$(date -Iseconds)" "$row"
sleep 1

- [[ -n "$row" ]]는 변수 내용이 비어 있지 않은지 검사합니다.
- || break는 그 검사가 실패할 때 반복문을 빠져나옵니다. 대상이 사라지거나 Z로 제외되면 출력 행이 없어지는 것이 일반적인 종료 경로입니다.
- date -Iseconds는 초까지 포함하는 ISO 형식 시간과 시간대 정보를 출력합니다. +09:00은 UTC보다 9시간 빠른 시간대입니다.
- printf '%s,%s\n'은 시간, 쉼표, ps/awk 결과, 줄바꿈 순서로 출력합니다. \n이 줄바꿈입니다.
- sleep 1은 다음 조회 전 1초 대기합니다. ps·awk·date 실행 시간도 추가되므로 정확히 매 1.000초의 측정을 보장하지 않습니다.

시간은 ps 조회 뒤에 붙습니다. 즉 CSV 한 행은 모든 값이 완전히 같은 순간에 측정됐다는 뜻이 아니며 작은 수집 지연이 있습니다.

10. 마지막 메시지: CSV와 따로 읽기

echo "Monitoring ended: PID $pid is no longer running." >&2

뜻은 “해당 PID의 관제가 끝났습니다”입니다. >&2로 표준 오류에 보내 CSV 숫자 행과 분리합니다. 여기서 표준 오류는 오류·안내 메시지용 출력 통로이며, 그곳에 출력됐다고 해서 반드시 장애라는 뜻은 아닙니다.

이번 원본 monitor-11373.log
https://github.com/bidulgiya999/codyssey_work_B4-2/blob/main/plus_2026_11_10/evidence/oom-128-20261110-193545/monitor-11373.log에는 다음 안내가 있습니다.

Monitoring ended: PID 11373 is no longer running.

단, 이 문구는 스크립트가 빈 행을 받았을 때 출력한 안내입니다. ps 오류나 수집 실패도 빈 결과를 만들 수 있으므로 이 문구만으로 정상 종료·비정상 종료·종료 원인을 확정하지 않습니다. 이번 실험에서는 app.log, 종료 코드, 종료 후 ps와 함께 대조했습니다.

11. 실행 구문: 파일 분리와 백그라운드의 의미

다음은 사용 방법을 설명하는 예시입니다. 해당 PID가 실제 살아 있고, 현재 작업 폴더·AGENT_HOME·RUN_DIR가 준비돼 있다는 전제입니다. **현재 완료된 증거를 설명하기 위한 예시이며 그대로 재실행할 단계가 아닙니다.** 과거 PID 11373을 지금 조회해 당시 결과를 다시 얻을 수는 없습니다.

./monitor.sh "$WORKER_PID" \
  > "$RUN_DIR/monitor-$WORKER_PID.csv" \
  2> "$RUN_DIR/monitor-$WORKER_PID.log" &
MONITOR_PID=$!

| 문법 | 뜻 | 목적 |
|---|---|---|
| ./monitor.sh | 현재 폴더의 스크립트 실행 | 의도한 관제 파일 선택 |
| "$WORKER_PID" | 작업 자식 PID를 인수로 전달 | 실제 작업 프로세스 관찰 |
| > | 표준 출력을 파일로 저장; 기존 파일이면 덮어씀 | CSV 보존 |
| 2> | 표준 오류를 별도 파일에 저장 | 안내·오류와 CSV 분리 |
| & | 백그라운드에서 실행 | 앱과 관제를 동시에 진행 |
| $! | 가장 최근 백그라운드 작업의 PID | 시작한 관제 작업을 나중에 기다리거나 정리 |

MONITOR_PID는 관제 스크립트 PID이며 WORKER_PID는 대상 앱 PID입니다. 앱을 백그라운드로 실행한 직후의 $!와 monitor를 실행한 직후의 $!는 서로 다릅니다. 부모 실행기만 관측하면 실제 메모리 작업 자식의 증가를 놓칠 수 있어 부모와 자식을 각각 기록했습니다.

종료 상태를 남길 때에는 wait "$APP_PID" 직후 $?를 저장했습니다. $?는 바로 앞 명령의 종료 상태이므로 다른 명령을 사이에 넣으면 값이 바뀝니다. 종료 코드
https://github.com/bidulgiya999/codyssey_work_B4-2/blob/main/plus_2026_11_10/glossary.md#exit-code는 종료 이유를 판단하는 보조 자료이며 앱 로그와 함께 읽어야 합니다.

13. 출력에서 말할 수 있는 것과 추가 증거가 필요한 것

| 관측 | 여기까지 말할 수 있음 | 이것만으로는 확정할 수 없음 |
|---|---|---|
| RSS가 여러 행에서 증가 | 상주 메모리 증가 추세가 있음 | 정확한 누수 코드 위치, 앱 종료 주체 |
| PID가 조회됨 | 그 시점에 프로세스 항목이 존재 | 실제 요청 처리·작업 진행 |
| ps CPU가 낮음 | 실행 시간 평균이 낮음 | 짧은 순간 부하도 항상 낮음 |
| S 또는 futex 대기 | 대기 상태·동기화 대기 위치 | 교착 확정; 정상 대기도 가능 |
| 관제 종료 안내 | 더 이상 출력 행을 수집하지 못함 | MemoryGuard·커널·수동 중 누가 종료했는지 |

top
https://github.com/bidulgiya999/codyssey_work_B4-2/blob/main/plus_2026_11_10/glossary.md#top의 구간 사용률과 ps 평균은 측정 기간이 다릅니다. Deadlock에서는 스레드 대기
https://github.com/bidulgiya999/codyssey_work_B4-2/blob/main/plus_2026_11_10/glossary.md#futex뿐 아니라 마지막 로그의 자원 소유와 순환 대기를 확인했습니다.

현재 스크립트는 PID만 기억합니다. PID가 나중에 다른 프로세스에 재사용되는 경우까지 구분하지 않으므로 운영 개선 시 PID와 시작 시각·실행 파일을 함께 확인할 필요가 있습니다. 수집 오류를 따로 남기고, 증가율·지속 시간 알림·로그 회전 등을 추가하는 것도 개선 제안입니다. 이번 원본 스크립트에 이미 구현된 기능으로 설명하지 않습니다.

14. 평가 때 할 말

monitor.sh는 대상 PID를 약 1초마다 ps로 조회하고 필요한 열을 awk로 쉼표 구분 데이터로 바꿔 시간과 함께 저장합니다. RSS로 메모리 증가 추세를 보고, ps 평균 CPU와 top 구간 CPU를 구분했습니다. 마지막 관제 메시지만으로 원인을 정하지 않고 앱 로그·종료 상태·종료 후 프로세스와 대조했습니다.
